# DeepSeek Harness (DSH)

EvidenceSpine ships first-class delivery for **DeepSeek Harness 0.2.2-rc.5**
(the Electron "DeepSeek Harness" app and its bundled `dsh` CLI). DSH is not a
plain MCP config file: it composes a Cordis **profile** from bundle patch
layers, a profile patch layer, a machine-wide user patch layer, and optional
`--patch` overlays. EvidenceSpine writes exactly one managed block into the
machine-wide user patch layer, so the MCP client row is available to every
profile without touching a profile or the GUI Settings state.

Everything below was verified against the shipped 0.2.2-rc.5 app on macOS.
DSH patch semantics are internal and version-coupled: re-run
`evidencespine harness doctor` and the `--dump-config` checks after a DSH
upgrade.

## Profiles

DSH profiles are bundles plus patch layers. The profiles shipped in
0.2.2-rc.5 are:

| Profile | What it is | CLI-composable? |
|---|---|---|
| `desktop` | The Electron app profile; managed exclusively by the app | no (`--dump-config --profile desktop` errors by design) |
| `web` | Local web UI (the GUI surface) | yes |
| `headless` | Non-interactive CLI/headless sessions | yes |
| `acp` | Agent Client Protocol host | yes |
| `sdk` / `sdk-minimal` | Embedded SDK profiles | yes |

There is **no `tui` profile** in 0.2.2-rc.5 (`--profile tui` reports that it
does not exist). Users who expect a TUI are on `headless`.

The patch-layer precedence, highest first:

1. `--patch <file>` launcher overlays (repeatable);
2. the machine-wide user patch `$DSH_HOME/cordis.patch.yml`;
3. the active profile patch `$DSH_HOME/profiles/<name>/cordis.patch.yml`;
4. bundle patches from the profile's `package.json` `dsh.profile.bundles`.

EvidenceSpine installs at **layer 2**, so one file covers every profile.

`DSH_HOME` defaults to `~/.dsh` (an explicit env var wins; blank means
unset). The desktop app sets it in its own environment; when you install from a
shell, export the same value if you use a custom home.

## One-command install

```sh
# default: project-scope install targeting the machine-wide home patch
evidencespine harness install --harness dsh --target-dir /path/to/repo

# preview the exact block without writing anything
evidencespine harness install --harness dsh --target-dir . --dry-run

# also merge the managed AGENTS.md block (opt-in; normally unnecessary)
evidencespine harness install --harness dsh --target-dir . --with-agents-md

# explicit executable (absolute path is strongly preferred)
evidencespine harness install --harness dsh --target-dir . --executable /abs/path/to/evidencespine
```

`--scope project` and `--scope global` both target the machine-wide
`$DSH_HOME/cordis.patch.yml`: DSH never auto-discovers repo MCP files, so
there is no project-scope MCP file to write. (The Python API additionally
accepts `scope="profile:<name>"` and writes a GUI-visible `mcp-manager` row
for one profile; the CLI does not expose that scope in 0.6.0, and it refuses
to touch a profile that already owns a manager row.)

The installer resolves `evidencespine` to an absolute path (PATH lookup, then
the running interpreter fallback), refuses to modify a file that is not a
top-level YAML sequence, and creates a timestamped
`cordis.patch.yml.bak-<UTC>` backup plus mode `0600` on first modification.

## What it writes

### `$DSH_HOME/cordis.patch.yml`

A single managed block, delimited by sentinel comments:

```yaml
# BEGIN EvidenceSpine (managed)
# EvidenceSpine - DSH MCP client row (generated by `evidencespine harness install --harness dsh`).
# Machine-wide user patch layer: applies to every DSH profile, above each profile's cordis.patch.yml.
# The row is merged by id; uninstall removes only this managed block.
- insert:
    - id: evidencespine-mcp
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: evidencespine
        transport: stdio
        command: '/absolute/path/to/evidencespine'
        args:
          - 'mcp'
          - '--base-dir'
          - '/absolute/path/to/repo/.evidencespine'
        cwd: '/absolute/path/to/repo'
        failOnStartupError: false
        startupTimeoutMs: 20000
# END EvidenceSpine (managed)
```

Field notes:

- The row is `@deepseek-ai/dsh-mcp-client` (one row per server, carries
  `serverName`), not an `mcp-manager` fleet entry. The client row is
  mounted by every profile; the manager exists only in web/desktop, and a
  profile patch **replaces** the manager entry's whole `servers` map, so
  writing a manager map blindly erases Settings-managed servers.
- `serverName` must match `[A-Za-z0-9_-]{1,32}` and is the tool namespace:
  tools surface as `mcp__evidencespine__<tool>`.
- **`command`, `args` paths and `cwd` must be absolute.** The stdio child
  inherits the DSH host process cwd (the Electron app usually runs from `/`),
  not the session workspace. A relative `--base-dir .evidencespine` would
  create the store in the wrong place.
- `cwd` is set to the project root (the enclosing git worktree when
  available).
- `failOnStartupError: false` keeps sessions alive when the side-car breaks;
  set it to `true` only if a missing/ broken spine should be fatal.
- `startupTimeoutMs` is 20000 by default; raise it for slow cold starts.
- `enabled` is a manager-entry field, not a client-row field. To disable the
  row, remove the managed block (or add `disabled: true` to the row if you
  manage a fork of it yourself).

### Project skill

The installer materializes `<repo>/.dsh/skills/evidencespine/SKILL.md` (a
relative symlink to the canonical `skills/evidencespine/SKILL.md` when
possible, otherwise a generated copy). DSH discovers it at rank 100, so the
skill is visible to every agent in the project.

### Nothing in the repo is required

No `.dsh/@-hosted config is needed for MCP. If you prefer a one-off project
overlay instead of the home patch, write the same `insert` block to a file
and launch with:

```sh
dsh web --patch "$PWD/.dsh/evidencespine.dsh.patch.yml"
```

DSH does not auto-discover that file; the flag is required.

## Verify

The `dsh` binary is **not on PATH** for the app install. Locate it at
`/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh`
(or set `DSH_CLI`). Compose the real, fully merged config and look for the
row:

```sh
CLI="/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh"

# both profiles must show the managed row
DSH_HOME="$HOME/.dsh" "$CLI" --dump-config --profile headless | grep -A12 evidencespine-mcp
DSH_HOME="$HOME/.dsh" "$CLI" --dump-config --profile web      | grep -A12 evidencespine-mcp

# the default view must NOT show it (proves it comes from the user layer)
DSH_HOME="$HOME/.dsh" "$CLI" --dump-default-config --profile headless | grep -c evidencespine-mcp   # 0

# one-off isolation test without touching any real profile
DSH_HOME=/tmp/dsh-test-home "$CLI" --profile headless --patch /tmp/esp.patch.yml --dump-config
```

`evidencespine harness install --harness dsh` runs the two
`--dump-config` compositions when the CLI is found and reports
`verification.composed_headless` / `verification.composed_web` in its JSON
result (verification never fails the install). Composition proves the row is
in the tree; it does not mount the plugin. For a live mount check, launch a
session and call a tool:

```sh
DSH_HOME="$HOME/.dsh" "$CLI" --profile headless "call build_brief for this repo"
```

In a live transcript you should see `mcp__evidencespine__build_brief`.

## Zero-install guidance (MCP instructions)

The highest-value DSH integration needs no file at all: EvidenceSpine's MCP
server returns a usage guide in `initialize.instructions`, and DSH injects
that text as a live system-prompt section named `mcp:evidencespine` (cap
32768 bytes; the server self-caps at 4000 characters). Every DSH agent in
every profile and repo therefore sees the operating rules as soon as the MCP
row exists. The same text is available at runtime as
`evidencespine://guide`.

## Optional `AGENTS.md`

DSH discovers instruction files per directory, in order: `AGENTS.md`,
`CLAUDE.md`, then `AGENTS.local.md` / `CLAUDE.local.md`; the project root
is the nearest ancestor with `.git` and files are cumulative root->cwd. Two
fixed user-global roots are also read: `$DSH_HOME/AGENTS.md` and
`$DSH_AGENTS_HOME/AGENTS.md` (default `~/.agents/AGENTS.md`).

- Prefer `--with-agents-md` over writing `AGENTS.md` by hand. It merges a
  managed block (`<!-- evidencespine:begin -->` ... `<!-- evidencespine:end
  -->`) and never clobbers user text.
- **Never** write `$DSH_HOME/AGENTS.md`: it is user-global and shared by every
  project.
- Do not invent new filenames; DSH only discovers the four names above.
- This block duplicates the MCP instructions. It is useful for clients that
  read `AGENTS.md` but not MCP instructions, and to feed Codex/Claude Code as
  well; for DSH alone it is optional.

## Skills

DSH skill roots, highest rank first: `<project>/.dsh/skills` (100),
`<project>/.agents/skills` (200), configured custom dirs (300),
`$DSH_HOME/skills` (400), `$DSH_AGENTS_HOME/skills` (500), bundled (600).
Format: a directory `<name>/SKILL.md` or a flat `<name>.md` **at the root's
top level** (nested paths are not discovered). Frontmatter requires `name`
and `description`; optional keys are `whenToUse`, `metadata`,
`disable-model-invocation` and `user-invocable` (booleans accept
true/false/yes/no/on/off/1/0; camelCase legacy keys are rejected). Skill
directories are watched, so edits are picked up without a restart.

EvidenceSpine ships `skills/evidencespine/SKILL.md` and installs it as a
symlink under `.dsh/skills/`. Reinstall refreshes generated copies; a
user-modified, marker-less copy is preserved instead of overwritten (pass
`EVIDENCESPINE_SKILL_SOURCE` to point the installer at a different canonical
file).

## Limits

- **No external lifecycle hooks.** DSH has no hooks file, hook flags, or
  session-start/stop/pre-compaction process hook an MCP side-car can register;
  events are in-process Cordis events for plugins only. There is therefore no
  automatic recall/retain delivery for DSH beyond MCP tools and instructions.
- **No TUI profile** in 0.2.2-rc.5.
- **No project slash commands / prompt files.** DSH commands are registered by
  plugins in process; DSH also does not consume MCP `prompts/@- (resources are
  consumed). Use the skill and MCP tools instead.
- **Env scrub.** DSH's stdio MCP child environment drops every `DSH_*` variable
  and anything matching `KEY|PASSWORD|SECRET|TOKEN` (case-insensitive). The
  server cannot read `DSH_SESSION_ID` (so harness hooks cannot identify the
  DSH session) and secrets must be declared explicitly in the row's `env`
  (or passed via headers).
- **No OAuth.** DSH's MCP client sends static headers only; a 401 is an
  ordinary connection failure. EvidenceSpine is a static bearer server, so
  stdio is the recommended transport; for streamable-HTTP, put the token in
  `headers` (DSH resolves Loader `!!js` expressions, e.g.
  `!!js "Bearer " + process.env.EVIDENCESPINE_MCP_AUTH_TOKEN`, but plain YAML
  validators will reject `!!js` by design; a literal header is the portable
  option).
- **Desktop profile is app-managed.** Never edit
  `$DSH_HOME/profiles/desktop/` from a script; the app owns it.
- **Version coupling.** Patch-row field names, mount behavior and the skill
  format are internal DSH contracts. Pin the DSH version you validated, and
  re-run verification after upgrades.

## Troubleshooting

| Symptom | Check / fix |
|---|---|
| Tools `mcp__evidencespine__*` missing | `--dump-config` shows the row? If yes, restart the app/session; if no, the home patch was not composed (wrong `DSH_HOME`, or the block sits after invalid YAML). |
| Store created in the wrong place | `command`/`args`/`cwd` must be absolute; re-install with `--executable` and an absolute `--target-dir`. |
| Server fails to start | Run the exact `command` and `args` by hand; check `startupTimeoutMs`; `failOnStartupError: false` keeps the session alive but tools never appear. |
| `invalid: not a top-level YAML sequence` | The home patch has non-sequence content; the installer refuses to modify it. Fix the file manually or use `--dry-run` and merge the block yourself. |
| `conflict: unmanaged evidencespine-mcp row` | An unmanaged row with the same id exists; remove it (or wrap it in the managed sentinels) so there is exactly one registration. |
| GUI Settings and installer disagree | The GUI Settings editor writes the profile patch; a profile `mcp-manager` entry replaces the whole servers map. Do not register the same server name twice. |
| Composition fails everywhere | A malformed `$DSH_HOME/cordis.patch.yml` breaks boot for every profile. Restore the `.bak-<UTC>>file` first. |
| Tool gap after editing settings | Manager entries re-sync; static client rows are not listed in `mcpManager.list()` and cannot be restarted from the GUI. Restart the app after changing the file. |

## Uninstall

There is **no `harness uninstall` CLI subcommand in 0.6.0**. Remove the
managed block manually, or call the module-level helper:

```python
from evidencespine.harness import dsh

result = dsh.uninstall_dsh(target_dir=".", scope="project", verify=True)
print(result)
```

That deletes only the block between `# BEGIN EvidenceSpine (managed)` and
`# END EvidenceSpine (managed)`, writes a backup, deletes the file if it
contained only the block, and re-runs the `--dump-config` composition (the
row must disappear). The installed skill under `.dsh/skills/evidence
spine/` is a symlink; remove it if you no longer want the skill.
